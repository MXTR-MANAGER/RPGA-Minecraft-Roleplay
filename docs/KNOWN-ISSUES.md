## 1. Какую версию ставить

> ### 🌐 Актуальная версия — [**56.1.0-alfa**](../versions/56.1.0-alfa/)
> > Это сборка, на которой работает сервер RPGA. Она же актуальна
> > для одиночной игры и для любого своего сервера.

### Статус всех версий

| Версия | Статус | Что делать |
|---|:---:|---|
| [**56.1.0-alfa**](../versions/56.1.0-alfa/) | 🌐 **Сервер RPGA** | **Ставить.** Единственная актуальная версия — и для сервера, и для одиночки |
| [30.0.2](../versions/30.0.2/) | ⛔ Устарела | Только если нужна версия без звуков и баг-репортов |

| [51.3-beta](../versions/51.3-beta/) | 🧪 **= альфа** · 🕳️ пусто | **Не ставить нигде.** Тот же код, что в альфе, только черновик |

### 🧪 Бета = альфа, и пусто — и для сервера, и для одиночки

> **51.3 и 51.4 — не отдельная старая ветка, а черновики той же линии.**
> Весь их код вошёл в **56.1.0-alfa** и был там доработан. Разница только
> в том, чего в бете **ещё не было**.

| | Что даёт бета 51.3 / 51.4 | Чего не даёт |
|---|---|---|
| 🌐 **Серверу** | **Ничего** | Ставить нельзя — не задеплоена, есть риски |
| 🏠 **Одиночной игре** | **Ничего** | Ноль фич, которых нет в альфе |
| 📦 **Смысл скачивания** | **Нулевой** | Оставлены только ради истории |

Ни одной фичи беты нет в 56.1.0-alfa — и наоборот, в альфе есть всё из бет
плюс звуки, баг-репорты, тюрьма v51.5, замки v51.6 и паспорт. Ставить беты
**не нужно нигде**.

### Почему беты 51.x раньше нельзя было ставить на сервер

Раньше беты запрещались к установке на сервер из-за трёх причин.
**В 56.1.0-alfa все три сняты:**

| Причина | Статус в 56.1.0-alfa |
|---|---|
| ⚠️ **Переименования айдишников** (`phone` → `rga_phone`, `smoke_grenade` → `smoke_grenade_1/2/3`, `uniform_medic` → `med_uniform`) | Остались, но это уже финальные имена — миграция завершена, ломать больше нечего |
| ⚠️ **Новые сетевые пакеты** — игроки с разными версиями вылетают | Остаётся актуальным: на клиенте и сервере должна стоять **одна и та же** версия |
| ⚠️ **Непроверенный на живых игроках код** | ✅ Исправлено — баги направлений пейлоадов исправлены, версия задеплоена на сервер |

> 📦 Беты остались в репозитории только для истории и сравнения.
> Полное сравнение — в [VERSION-GUIDE.md](../VERSION-GUIDE.md).

## 2. Критично: проверить перед релизом

> Все три бага присутствуют **и в актуальной версии 56.1.0-alfa**.
> Они не закрыты.

### 🔴 1. Перевод денег крашит мод

| | |
|---|---|
| **Где** | `item/RPGAMoneyItem.java:144-150` |
| **Что** | `MoneyTransferPayload` (id `rp-mxtr-rpga:money_transfer`) — **единственный** пейлоад мода, объявленный не в `RPGAPayloads.java` |
| **Почему ломается** | Он реализует `CustomPayload`, но **не зарегистрирован** в `PayloadTypeRegistry` (все 126 остальных пейлоадов зарегистрированы в `RPGACommonMod.java`) |
| **Симптом** | Любая попытка перевести деньги другому игроку → исключение на сервере |
| **Где вызывается** | отправка `RPGAMoneyItem.java:197`, приём `RPGAServerMod.java:160` |
| **Статус** | ⛔ не исправлено во всех версиях, включая 56.1.0-alfa |

**Как избежать:** не переводить деньги через GUI. Управляйте балансами
командой `/rpga setbalance <игрок> <сумма>` — см. [ADMIN-GUIDE.md](ADMIN-GUIDE.md).

### 🔴 2. Ранги фракции «Смотритель» показывают «Неизвестно»

| | |
|---|---|
| **Где** | `common/FactionRankSystem.java:26-50` |
| **Что** | В `FACTION_RANK_NAMES` есть 7 ключей: `fso`, `fsb`, `dps`, `mchs`, `med`, `sk`, `army` |
| **Почему ломается** | Ключа **`warden`** нет вообще |
| **Симптом** | `getRankTitle("warden", n)` возвращает заглушку `Неизвестно` (строка 58) для **всех** рангов 1–6 смотрителя |
| **Статус** | ⛔ не исправлено |

### 🔴 3. Навигационные точки исчезают при перезапуске сервера

| | |
|---|---|
| **Где** | `server/RPGAServerMod.java:6252` |
| **Что** | `private static final List<NavPointEntry> navPoints = new ArrayList<>()` |
| **Почему ломается** | Список живёт **только в оперативной памяти**. Файлового ввода-вывода нет **нигде** — ни в одном из 12+ JSON-файлов мода |
| **Симптом** | Игроки создают точки в Навигаторе телефона → после рестарта все точки пропали |
| **Клиентская копия** | `client/RPGAClientMod.java:110` и `:682` — зеркало того же списка |
| **Статус** | ⛔ не исправлено |

**Обходной путь:** точки приходится создавать заново после каждого рестарта.
Для постоянных точек используйте **блоки навигационных точек** (`navigation_point`)
— они хранятся в мире и не пропадают.

## 3. Баг-репорт говорит «не успешно», но уходит

> ### 🟡 Только в версии 56.1.0-alfa
> > Текст на экране вводит в заблуждение: репорт **реально отправляется**,
> > просто показывается не то сообщение.

### Что происходит

При отправке баг-репорта **с титульного экрана** (то есть когда игрок ещё
не в мире — `inGame() == false`) мод честно кладёт репорт в очередь
`config/rpga-bug-queue/` и затем показывает:

| Строка на экране | Что она значит на самом деле |
|---|---|
| `Спасибо, репорт принят` | Репорт **не отправлен прямо сейчас** |
| `Связи нет — репорт сохранён и отправится позже` | Связь на самом деле **есть** — просто мод не может отправить пакет, пока не в игре |
| `в очереди: 1` | Репорт в очереди, **но очередь сама опустеет** |

| | |
|---|---|
| **Где** | `client/BugReportService.java`, обработчик `lambda$send$1` |
| **Условие** | Отправка **не из игры** — с титульного экрана (`TitleScreenMixin.java:57`) |
| **Симптом** | Сообщение «нет связи, отправится позже», хотя через ~10 секунд репорт **уходит на сервер** и появляется в `config/rpga-bugs.json` |
| **Статус** | 🟡 косметический баг — сами репорты не теряются |

### Что происходит на самом деле

1. Игрок отправляет репорт с титульного экрана
2. Мод не может отправить сетевой пакет → пишет репорт в очередь `config/rpga-bug-queue/bug-*.json`
3. На экране появляется сообщение про «нет связи» — **это и есть ошибка формулировки**
4. `flushQueue()` на тике 200 (≈10 секунд) отправляет накопленное на сервер
5. Репорт оказывается в `config/rpga-bugs.json` — **ничего не потеряно**

### Как проверить

1. Запустить мод с титульного экрана
2. Отправить баг-репорт
3. Убедиться, что в `config/rpga-bug-queue/` появился файл `bug-*.json`
4. Зайти в мир на сервер
5. Через ~10 секунд проверить `config/rpga-bugs.json` на сервере — репорт там будет

### Как избежать

**Отправляйте баг-репорты из игры** — из меню паузы. В этом случае
мод отправляет пакет напрямую, без очереди, и сообщение корректное.

## 4. Средние проблемы

## 5. Мелочи

### 🟡 Два разных заголовка у одного экрана

**Где:** `block/FactionBarrelConfigScreen.java:29`

Заголовок экрана настройки фракционной бочки — `"Настройка бочки"` (без цвета), тогда как в других местах используется `"§6Настройка фракционной бочки"`. Визуальное расхождение, на работу не влияет.

### 🟡 Розыск при атаке на NPC

Два похожих места расчёта: `RPGAServerMod.java:3223` (1★) и `:3227` (2★). Проверка выбирает звезду по типу NPC — при отладке легко перепутать, какой случай срабатывает.

### 🟡 `wantedMinutes` в памяти

**Где:** `RPGAServerMod.java:110` — `HashMap<UUID,Integer>`

Сроки розыска пересчитываются по формуле «звёзды × 5 минут» (`addWantedCrime`, строки 3050 и 3065). Часть нарушений задаёт срок вручную через перегрузку `addWantedCrime(p, crime, stars, minutes)` с `Math.max(1, minutes)`.

## 7. Как сообщить о баге

### Способ 1 — прямо в игре (быстро, рекомендуется)

В версии **56.1.0-alfa** есть встроенная отправка репортов:

| Где | Как |
|---|---|
| ⏸ **Меню паузы** | кнопка **«Баг-репорт»** → заполнить категорию, имя, описание |
| 🏠 **Титульный экран** | отправка с главного меню (репорт уйдёт, как только зайдёте в мир) |

Репорт попадает на сервер в `config/rpga-bugs.json`. Репорты отправляются
анонимно — мод обещает, что личная информация не будет раскрыта.

> ⚠️ Отправляйте из **меню паузы**: при отправке с титульного экрана мод
> показывает сообщение «нет связи», хотя репорт всё равно уходит — см.
> [раздел 3](#3-баг-репорт-говорит-не-успешно-но-уходит).

### Способ 2 — через GitHub Issues

1. Откройте **Issues** → **New issue** → **Bug report**
2. Обязательно укажите:
   - **Версию мода** (видна в панели модов или в названии jar)
   - **Режим**: одиночная игра / сервер RPGA / свой сервер
   - **Версию Minecraft и Fabric Loader**
3. Опишите: что делали → что ожидали → что получилось
4. Приложите лог: клиент — `logs/latest.log`, сервер — `logs/latest.log` на сервере
5. Если версии у всех разные — укажите это явно, **это частая причина «не работает»**

## 🔧 Чек-лист релиза новой версии

Для разработчика — порядок действий при выпуске билда:

1. Поднять `version` в `build.gradle`
2. Обновить имя jar в скрипте деплоя
3. Собрать: `gradlew.bat build --offline -x test -Dorg.gradle.jvmargs=-Xmx2g`
4. Скопировать jar клиенту: `%APPDATA%\.minecraft\mods\`
5. Задеплоить на сервер, **дождаться подтверждения**
6. Перезапустить сервер **вручную** (панель)
7. Обновить таблицы в [README](../README.md), [VERSION-GUIDE.md](../VERSION-GUIDE.md), [CHANGELOG.md](../CHANGELOG.md)
8. Создать git-тег `v<версия>` и запушить
9. Записать сюда найденные при тестах проблемы
