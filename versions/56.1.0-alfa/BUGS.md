## 💥 Баг №1 — Перевод денег крашит игру

**Самый важный баг мода.** Он есть во **всех** версиях начиная с `30.0.2`
и **ни разу не был исправлен**.

| | |
|---|---|
| **Где** | `item/RPGAMoneyItem.java:144-150` (объявление), `:197` (отправка) |
| **Что** | `MoneyTransferPayload`, id `rp-mxtr-rpga:money_transfer` — единственный пейлоад мода, объявленный не в `RPGAPayloads.java` |
| **Почему ломается** | Реализует `CustomPayload`, но **не зарегистрирован** в `PayloadTypeRegistry`. Остальные 126 пейлоадов зарегистрированы в `RPGACommonMod.java` — этот пропущен |
| **Что видит игрок** | Игрок открывает экран денег (кошелёк / банкомат) и жмёт **«Перевести»** или **«Снять»** → игра падает с ошибкой → **клиент вылетает на рабочий стол** |
| **Деньги** | **не списываются и не переводятся** — списание возможно только после ответа сервера, а ответа не было |
| **Кто страдает** | только отправляющий игрок. Сервер продолжает работать, остальные игроки не затрагиваются |
| **Технически** | `NullPointerException` при кодировании пакета: `CustomPayload$1.getCodec()` возвращает `null` для незарегистрированного id, и `PacketCodec.encode()` вызывается на `null` |
| **Статус** | ⛔ не исправлено |

**Как избежать:**
1. Не пользоваться экраном перевода — управляй балансами командой
   `/rpga setbalance <игрок> <сумма>` (см. [ADMIN-GUIDE.md](../../docs/ADMIN-GUIDE.md))
2. Или переводи деньги внутриигровыми предметами / банкоматом на стороне сервера

## 🐛 Баги без вылета

### 🔴 Ранг «Смотрителя» показывает «Неизвестно»

| | |
|---|---|
| **Где** | `common/FactionRankSystem.java:26-53` |
| **Что** | В `FACTION_RANK_NAMES` 7 ключей: `fso`, `fsb`, `dps`, `mchs`, `med`, `sk`, `army` |
| **Почему** | Ключа **`warden`** нет вообще |
| **Симптом** | `getRankTitle("warden", n)` возвращает заглушку `Неизвестно` для **всех** рангов 1–6. Игрок видит «Неизвестно» в чате, в форме, в списке игроков. Всё остальное по фракции работает |
| **Статус** | ⛔ не исправлено |

### 🔴 Навигационные точки исчезают после рестарта сервера

| | |
|---|---|
| **Где** | `server/RPGAServerMod.java:6252` |
| **Что** | `private static final List<NavPointEntry> navPoints = new ArrayList<>()` |
| **Почему** | Список живёт **только в оперативной памяти**. Файлового ввода-вывода нет **нигде** — ни в одном из 12+ JSON-файлов мода |
| **Клиентская копия** | `client/RPGAClientMod.java:110` и `:682` — зеркало того же списка |
| **Симптом** | Игроки создают точки в Навигаторе телефона → после рестарта все точки пропали |
| **Статус** | ⛔ не исправлено |

**Обходной путь:** точки приходится создавать заново после каждого рестарта.
Для постоянных точек используйте **блоки навигационных точек** (`navigation_point`)
— они хранятся в мире и не пропадают.

### 🟡 Баг-репорт с титульного экрана врёт

| | |
|---|---|
| **Где** | `client/BugReportService.java`, обработчик `lambda$send$1` |
| **Условие** | отправка **не из игры**, с титульного экрана (`TitleScreenMixin.java:57`) |
| **Что видит игрок** | Сообщение «Связи нет — репорт сохранён и отправится позже» |
| **Что на самом деле** | Связь **есть**. Репорт реально уходит через ~10 секунд и попадает в `config/rpga-bugs.json` |
| **Как происходит** | 1) мод не может отправить пакет до входа в мир → пишет репорт в очередь `config/rpga-bug-queue/bug-*.json` 2) показывает неверное сообщение 3) на тике 200 (≈10 сек) `flushQueue()` отправляет накопленное |
| **Статус** | 🟡 косметический — репорты **не теряются** |

**Как избежать:** отправляйте баг-репорты **из меню паузы**, а не с титульного
экрана — тогда сообщение корректное.
